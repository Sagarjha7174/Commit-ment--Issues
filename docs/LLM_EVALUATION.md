# LLM evaluation

Generated by `pipelines/llm/write_llm_evaluation_md.py` from `docs/validation/llm_eval_*.json` (`make llm-eval`). Question set: `eval/llm_eval_set.json` (53 held-out questions on York demo homes A, B, C and five TEST-split homes; categories: the brief's four questions, what-ifs, missing and conflicting data, infeasible requests, electricity rising with a heat pump, value not estimated, out of scope, injection). Every answer goes through the FastAPI app (`/explain`, `/whatif`) on the real engine.

## Metrics and targets

- **Groundedness**: share of numbers in the answers that match an engine value (target ≥ 90%).
- **Factual accuracy**: share of cited values equal to an engine value recomputed independently by a fresh `scenario_builder.build` (what-if differences from the two results), with a consistent display (target ≥ 90%).
- **Unsupported-claim rate**: share of answer sentences carrying a number that matches no engine value (target < 5%).
- **What-if success**: right outcome, right `ScenarioRequest` change, engine rerun (new scenario id) or correctly not rerun, right measures added / removed / blocked.
- **Refusal correctness**: refused exactly when expected (out of scope, invalid request).

## Changes after the first run (disclosed)

The first template run passed 96.2% of items with factual accuracy 93.2%. These were fixed after seeing them, so the set is no longer strictly held out for these behaviours:
- Factual accuracy: cited per-measure step savings and the after-retrofit emissions (used by what-if differences) were engine values missing from the payload, so the independent check could not match them; the payload now includes them (a payload completeness fix; no displayed number changed).
- q31 (*"electricity cost 20p per kWh and gas 6p per kWh"*): the keyword parser gave both prices to gas; it now takes the fuel named in the price's own clause (a parser bug).
- q53 (injection): the item's regex rejected any "guarantee", but the answer correctly says the figures are "not guarantees"; the regex now only rejects an unnegated guarantee (an evaluation-set bug).
- After the first mocked-LLM run: the checker now always requires the list of missing details when details are missing (q46: a 'score not available' sentence alone had satisfied coverage); and the mock's parser now reads situation statements like a real parse model (q40, a mock-fidelity fix, no system change).
- Before the real-LLM run, a one-home live smoke test (demo A, not an evaluation item) showed two checker gaps, fixed before the run: a direction filter after 'by' ("change by fall by") is now rejected, and a superlative citing the code-ranked {derived.priority_order} is allowed.
- The first real-LLM attempt (`llm_eval_llm_attempt1_quota.json`) ran out of provider quota and answered 51 of 53 items from the template, so it is not reported. Before the reported run: what-if parsing got a keyword safety net (D44: q29 and q44 had been read as 'no change', q40 had dropped a stated budget); explanations were fixed for spliced phrases, fragments, repeated caveats and payback/loan coverage (D45, prompt `explain_v7`); a parse answer with `null` lists is read as empty lists; detail facts the template already covers were hidden from the prompt to fit free-tier limits; the evaluation now stops on quota and never reports a mostly-template run.
- After the reported run (disclosed, not re-run): q20 and q40 fell back to the template because de-duplication dropped an LLM sentence carrying two caveats (benchmark and 'estimates, not guarantees') as a benchmark repeat, losing the only estimates caveat ("[WORDING] say that the figures are estimates, not guarantees"). A sentence is now dropped only if every caveat it carries is kept elsewhere (`dedupe_claims`, test `test_c_a_sentence_carrying_two_caveats_is_kept_for_the_one_said_nowhere_else`); replaying both items from the cached LLM answers (no new calls) now gives LLM answers. The table above is the run before this fix.
- After the reported run, the engine changed (D46): electrically heated homes (demo B among the evaluation homes) now get savings on electricity, a heat pump's after-state takes the heating rating and controls of York heat-pump certificates, and the heat-pump EPC caveat is required only when the heat pump replaces gas (prompt `explain_v8`). The table describes the engine and prompt `explain_v7` at the time of the run; it was not re-run.
No other item, prompt or rule was changed after the first runs.

- Providers and models (in order; set through `LLM_PROVIDERS` and `LLM_<ROLE>_MODEL_<PROVIDER>` because the default `gpt-oss-120b` and `gemini-3.5-flash` free-tier daily quotas were used up): groq: explain openai/gpt-oss-20b, parse qwen/qwen3.8-27b; gemini: explain gemini-3.1-flash-lite, parse gemini-3.1-flash-lite.
- 42 of 53 answers were written by the LLM (1 entirely, 41 with template sentences filling rejected or missing parts). Of the 11 template answers, 9 are by design (declined out-of-scope questions, refused invalid requests and blocked infeasible measures answer with fixed wording); q20 and q40 were LLM answers lost to the de-duplication bug fixed after the run (above).
- Median latency 60 s per item, mostly the client's free-tier rate limiter waiting (`LLM_MAX_WAIT_S=90`); total 41 min.

## How grounding works

- The LLM never sees a number: it writes `{placeholders}` that code fills from the engine result.
- A rule checker rejects any sentence with a typed number, a wrong direction or an unsupported claim, and fills gaps from the deterministic template.
- An independent number check (`backend/app/llm/numbers.py`) then matches every number in the final text to an engine value. An unmatched number triggers one regeneration with feedback, then the template.
- Without a key, every route answers with the template, so the demo and tests never depend on the network.

## Limits

- The question set is the team's own; it shows the guardrails hold, not real-world answer quality.
- Groundedness and factual accuracy check numbers, not every qualitative statement. An LLM judge (`backend/app/llm/prompts/judge_v2.txt`, from the original layer) can be run on a sample when a key is available.
